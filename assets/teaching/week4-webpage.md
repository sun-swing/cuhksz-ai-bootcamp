## 1. 为什么值得做这一步

**先问一个问题：你有没有一个"能发出去"的个人主页？**

大多数同学的答案是：没有。你的作品散在——

- 朋友圈（三天可见）
- 相册（自己都找不到）
- 电脑文件夹（别人拿不到）
- 简历（只有一行字"熟悉办公软件"）

**这周要解决的就是这件事：把你这三周攒的东西，变成一个能放进简历、能发给同学、能在面试时打开给 HR 看的链接。**

而且这件事的边际价值很高：

| 场景 | 有个人网页 | 没有 |
| --- | --- | --- |
| 投简历 | 简历末尾一行链接，直接展示作品 | 只有文字描述 |
| 面试 | "我做了个东西，您扫这个码" | 口头解释半天 |
| 社团/比赛 | 一个链接就是你的作品集 | 需要现场演示 |
| 加同学微信 | 主页即名片 | "我朋友圈有，你翻翻" |

**更要紧的是**：你这三周做的 Skill、知识库、跑出来的成果，正好就是网页的素材。**前三周是在攒东西，这周是把它装进橱窗。**

## 第 1 步：先定内容，再动手（别跳过）

**最常见的失败方式是：一上来就让 AI"帮我做个个人网页"。** 结果做出来一个漂亮的空壳，你自己都不知道往上放什么。

**正确的顺序是：先想清楚放什么，再让它做。**

### 一个个人网页，4 个模块就够了

| 模块 | 作用 | 放什么 |
| --- | --- | --- |
| **① 我是谁** | 3 秒内让人知道你是谁 | 名字、学校专业年级、一句话定位 |
| **② 我会什么** | 证明你有能力 | 技能标签、工具使用经验 |
| **③ 我做过什么** | **最值钱的部分** | 3–5 个作品/项目，每个带截图和一句话说明 |
| **④ 怎么找我** | 让人能联系你 | 微信/邮箱/GitHub（放你愿意公开的） |

### ★ 如果你做了第 2 周的知识库：这些内容不该你硬想

**第 2 周说过，那 40 分钟的投资在第 4 周兑现。现在就是兑现的时候。**

上面那 4 个模块，**全是"私人知识"**——AI 不知道，网上也搜不到。
但你的知识库里已经有了。所以**别自己硬憋**，直接让它读：

```
我要做个人网页，需要准备 4 个模块的内容：
① 我是谁　② 我会什么　③ 我做过什么　④ 怎么找我

请你先读我 ima 知识库「______」里的知识页，尤其是关于我的部分，
然后基于你读到的内容，帮我起草这 4 个模块。

要求：
1. 只用你在知识库里真的读到的信息，**不要编造**
2. 信息不够的地方，明确列出来问我，不要自己填
3. 语气像我自己，不要像模板
4. 先给我一版草稿，我提意见你再改
```

**为什么要这么做，而不是随便让 AI 写一版？**

| | 直接让 AI 写 | 让它读知识库再写 |
| --- | --- | --- |
| 它知道的你 | 什么都不知道 | 你的经历、偏好、在做的项目、你的表达习惯 |
| 结果 | 一版谁看都一样的通用介绍 | **只有你能写出来的那一版** |
| 你要改的 | 几乎全要重写 | 改几句就行 |

> 💡 **这就是第 2 周讲的"公共知识 vs 私人知识"最直接的回报。**
> 同一个 AI，喂了私人知识之后，给你的东西完全是两个档次。

**如果你没做第 2 周的知识库**，也没关系——用下面的方法一样能做出来。

### 素材不够？让 AI 帮你挖（替代方案）

跟 WorkBuddy 说：

```
我想做个人网页，但我不知道放什么。
请你当面试官，一次问我一个问题，帮我把素材挖出来。
从"你这学期做过什么"开始问，问到你觉得素材够了为止。
问完把挖掘到的内容整理成一份"网页内容清单.md"，我先看这份清单。
```

> 💡 其实这个方法就是"临时采访"。**做了知识库的同学等于跳过了这一步**——
> 因为第 2 周已经采访过了，而且结果一直存在你的知识库里，随时能调出来。

> ⚠️ **隐私提醒**：不要在网页上放手机号、身份证、家庭住址、真实班级门牌号。微信二维码建议用小号或者干脆不放，需要联系方式的写成「邮箱」或「微信：同姓名」。

**✅ 检查点 1**：你有一份确认过的「网页内容清单」，4 个模块都有内容。
（有知识库的同学：这份清单是 AI 读你的知识页生成的，你只做了补充和确认。）

## 第 2 步：让它生成页面（用这套标准结构）

跟 WorkBuddy 说这一段：

```
按这份内容清单帮我做个人网页。
要求目录结构必须是下面这样，我要自己拿去部署：

我的网页/
├── index.html      ← 页面骨架和内容
├── style.css       ← 所有的样式（配色、字体、排版、动画）
├── script.js       ← 所有的交互（导航、动画、按钮效果）
└── assets/         ← 素材文件夹
    ├── images/     ← 图片（头像、作品截图）
    └── icons/      ← 图标

硬性要求：
1. HTML 里只放内容结构，样式全部写在 style.css 里，交互全部写在 script.js 里
2. 所有引用素材的路径必须是"相对路径"，比如 assets/images/avatar.png，不要用绝对路径
3. 所有链接和资源都得能直接双击 index.html 打开就看到，不依赖任何需要联网加载的外部库
4. 响应式：手机和电脑上都要好看，手机上是单列
5. 风格：______（比如"深色科技风" / "简约白底" / "清爽蓝白"）
6. 加上平滑滚动、进场动画、导航栏高亮这几个小交互

生成完告诉我每个文件是干什么的。
```

### 为什么一定要这个结构？

因为它直接对应你后面要做的两件事：

| 文件 | 为什么单独拆出来 |
| --- | --- |
| `index.html` | 只放内容。想改文案的时候直接改这里，不会碰坏样式 |
| `style.css` | 只放样式。想换配色、换字体，改一个文件全局生效 |
| `script.js` | 只放交互。出问题时排查范围小 |
| `assets/` | 素材集中放。部署的时候整个文件夹一起传，不会漏图 |

**一个文件写到底的网页，改三次就没人能维护了——包括你自己。**

### 关于路径绑定（部署最容易翻车的地方）

**只用相对路径，不用绝对路径。**

| ❌ 会翻车 | ✅ 正确 |
| --- | --- |
| `C:\Users\我\Desktop\网页\assets\头像.png` | `assets/images/avatar.png` |
| `/Users/me/web/style.css` | `style.css` |
| `http://localhost:8080/logo.svg` | `assets/icons/logo.svg` |

**为什么？** 因为绝对路径只在你自己的电脑上有效。上传到任何平台，路径全变，图片全碎。

**✅ 检查点 2**：生成了 4 个文件/文件夹，结构跟你要求的一致。

## 第 3 步：本地打开看，改到你满意

### 怎么看

**Windows**：打开 `我的网页` 文件夹，**双击 `index.html`**，会自动用默认浏览器打开。

**macOS**：同样双击 `index.html`。如果没反应，右键 →「打开方式」→ 选 Chrome / Safari / Edge。

> 💡 想看手机上是什么样？在浏览器里按 `F12`（Mac 是 `Cmd + Option + I`）打开开发者工具，点左上角的手机图标，就能切成手机预览。

### 怎么改（全程只用嘴说）

| 你想改什么 | 就对 WorkBuddy 说 |
| --- | --- |
| 颜色太丑 | 「主色调改成深蓝配青绿，参考腾讯云官网的配色，对比度要够，文字在深色背景上必须清晰」 |
| 字太小 | 「正文字号调到 16px，行高 1.8，标题层级拉开差距」 |
| 手机上是乱的 | 「手机上打开时，作品卡片要单列显示，字号适当缩小，导航栏收成一个汉堡菜单」 |
| 想加东西 | 「在'我做过什么'下面加一个'我的 AI 技能'模块，用标签样式展示，每个标签鼠标移上去有轻微放大效果」 |
| 动画太花 | 「进场动画改成只做淡入上移，200 毫秒，别太夸张」 |
| 想换排版 | 「作品卡片改成左右交错布局，图片在左文字在右，下一行反过来」 |

**改完记得刷新浏览器**（`F5` / `Cmd + R`）才看得到效果。

### 一个提效小技巧

让 WorkBuddy 一次给你 **2–3 个风格版本**对比：

```
保持内容不变，给我 2 个不同风格的版本：
版本 A：深色科技风
版本 B：浅色简约风
放在两个不同的文件夹里，我对比完选一个。
```

**✅ 检查点 3**：你在浏览器里打开过，至少改过 1 轮，手机上预览也看过。

## 第 4 步：让它上线（这一步最爽）

**做完不上线，等于没做。** 下面三个方案，从易到难，选一个：

### 方案 A：让 WorkBuddy 一键部署（最省事，推荐）

直接说：

```
帮我用最简单的方式把这个网页部署上线，给我一个能在手机上打开的公网链接。
部署完把链接和"以后我要更新内容时该怎么做"告诉我。
```

它会调用部署能力，把网页传到一个可访问的地址，**给你一个 `https://` 开头的链接**。

拿到链接后：
1. **在手机上打开一次**，确认能用
2. 把链接存到微信收藏，**面试/聊天时随时能调出来**

### 方案 B：EdgeOne Pages / CloudStudio 之类的静态托管

跟 WorkBuddy 说：

```
帮我把这个网页部署到静态托管平台，用最佳实践来：
1. 先检查我的目录结构和相对路径有没有问题（部署前排查）
2. 告诉我需要在平台上做哪些设置
3. 部署完给我链接
4. 顺便写一份"下次更新内容后怎么重新部署"的三步说明
```

### 方案 C：GitHub Pages（想顺便练手就用这个）

适合想往简历上写"会用 Git"的同学。跟 WorkBuddy 说：

```
帮我把这个网页部署到 GitHub Pages，手把手带我：
1. 需要哪些前置条件（账号、Git 环境）
2. 每一步的命令和该点哪里
3. 怎么拿到最终的访问链接
4. 以后内容更新后，怎么重新发布
```

> ⚠️ **上线后必须自查一遍**：把链接发给一个同学，让他在他手机上打开。因为**路径问题只有换设备才会暴露**——你本机打开正常，不代表别人能看到。

### 上线后的三件小事

1. **加一个二维码**：让 WorkBuddy 把你的网页链接生成二维码图片，放到简历里
2. **写进简历**：在简历最上方放一行「个人主页：https://xxx」
3. **发给群里的同学**互相看看，**顺手收集一轮反馈**（这也是你的社群互动素材）

**✅ 检查点 4**：你拿到了一个 `https://` 开头的链接，并且在别人手机上打开过。

## 7. 卡住了怎么办

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 双击打开是空白页 | HTML 有语法错误 | 对 WorkBuddy 说「index.html 打开是白屏，帮我检查语法错误并修好」 |
| 图片不显示（红叉/空框） | 路径错了，或图片没放进 assets | 说「图片加载不出来，帮我把所有资源路径改成相对路径，并确认文件都在 assets 里」 |
| 本机能开，别人打不开 | 用绝对路径，或部署时漏传了 assets | 说「部署后图片都碎了，帮我全局排查绝对路径，改成相对路径后重新部署」 |
| 手机上看排版全乱 | 没做响应式 | 说「手机预览排版乱了，帮我加响应式：750px 以下单列显示，导航收成汉堡菜单」 |
| 部署后样式丢失 | 没上传 style.css，或文件名大小写不一致 | 确认 `style.css`、`script.js` 都在同一个目录，且文件名完全一致（大小写敏感） |
| 改了没生效 | 浏览器缓存 | 按 `Ctrl + F5`（Mac `Cmd + Shift + R`）强制刷新 |
| 想换风格但越改越乱 | 改动太多、方向不明 | 说「给我 2 个全新的风格版本，放两个文件夹，我从头选一个」 |
| 不会部署，平台太复杂 | 选了最难的方案 | 退回方案 A，直接让它一键部署 |

## 附录：给想深挖的同学

### 三个文件分别管什么？

用一个"房子"的比喻：

| 文件 | 比喻 | 什么时候改它 |
| --- | --- | --- |
| `index.html` | **毛坯房的结构**——几个房间、墙在哪 | 想加/删/改内容 |
| `style.css` | **装修**——墙漆颜色、家具摆放 | 想换配色、字体、间距 |
| `script.js` | **电器和开关**——按一下就亮 | 想改交互效果、加功能 |

**为什么必须分开？** 因为三种改动发生的频率和风险完全不同。分开之后，改文案不会误删样式，换配色不会碰坏交互。

### 什么时候需要"上网加载"的库？

**第一版不要用。** 因为：

1. 网络慢的时候页面会闪一下白
2. 有些库在学校的网络环境下加载失败
3. 部署到某些平台会有跨域问题

**先用纯 HTML + CSS + JS 做出来**，跑通了、上线了，再考虑升级。

### 这个网页和你的 AI 工作流的关系

到这里，你的四周闭环才真正合上了：

```
 Week 1  WorkBuddy（干活）
              ↓ 会用了工具
 Week 2  知识库（记事 + 沉淀）
              ↓ 形成了私人知识
 Week 3  Skill（把经验固化下来）
              ↓ 有了可复用的能力
 Week 4  个人网页（展示）
              ↓ 用知识库里的私人知识生成内容
        让机会来找你
```

**注意最后一步的箭头是从"知识库"指过来的，不是从"网页"自己。**

这就是为什么第 2 周花的 40 分钟值得：**第 4 周这个网页的内容，是从你前面积累的私人知识里长出来的，不是当场编出来的。**

**这四样东西合起来，才是"会用 AI"的完整定义**——不是会用某个工具，
而是**有一套自己的 AI 工作流，并且能把它变成看得见的产出。**
