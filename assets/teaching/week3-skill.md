## 1. 先搞懂：Skill 到底是什么

**一个比喻就够了：**

> Skill = **给 AI 的一本"专项作业手册"**。
>
> 你不在场的时候，AI 照着这本手册就能把这件事做到和你亲手做一样的水准。

**为什么需要它？** 举个真实的例子：

你每周都要写一份社团活动周报。每次你都要跟 AI 说一大堆：

> "帮我把这周的聊天记录整理成周报，要有活动名称、时间、参与人数、遇到的问题、下周计划，语气别太官方，控制在 500 字，格式用 Markdown，不要加标题……"

第一次说还行，第二次、第三次、第十次呢？**每次都要重复一遍，而且每次说得还不完全一样，结果就忽好忽坏。**

**有了 Skill 之后**，你只要说一句：

> 「用社团周报 Skill 处理这周的记录」

它就按你固化下来的标准流程，稳定产出同样的质量。

### Skill 和"每次都跟它说一遍"的区别

| | 每次都口述 | 做成 Skill |
| --- | --- | --- |
| 你要说的话 | 几百字，每次重打 | 一句话 |
| 结果稳定性 | 忽好忽坏 | 稳定 |
| 能分享给别人吗 | 不能 | 能（导出文件夹给同学） |
| 能长期沉淀吗 | 不能 | 能，越改越好 |

**一句话结论**：Skill 是把你脑子里的"隐性经验"，变成能复用、能传下去的东西。

## 第 1 步：找到"值得做成 Skill"的那件事（最关键）

不是所有事都值得做成 Skill。**先做筛选，别急着动手。**

### 三个判断标准，满足全部再往下做

| 标准 | 自检问题 |
| --- | --- |
| **① 会重复** | 这件事我做过 ≥3 次了吗？以后还会做吗？ |
| **② 有套路** | 我每次的步骤其实差不多吗？（如果需要每次重新想，就不适合） |
| **③ 有明确输出** | 做完会产出一个具体东西吗？（一份文件、一张表、一段文、一个网页） |

**✅ 适合做成 Skill 的：**
改简历、写周报、检查论文格式、整理课件笔记、生成复习计划、把截图转成表格、给社团写推文、批量重命名文件……

**❌ 不适合做成 Skill 的：**
"帮我想个创意"（没套路）、"跟我聊天"（没输出）、"帮我搜一下××"（太简单，直接问就行）

### 想不出来？用这一句问 WorkBuddy

```
我这学期经常做的重复性事情有这些：______（随便列几件）
请你帮我判断：哪 1 件最适合做成 Skill？
判断标准是：会重复做、步骤有固定套路、能产出明确的东西。
选好之后告诉我为什么选它，以及不选其他的原因。
```

### 参考：4 个校园版 Skill 选题（挑一个直接抄）

| Skill 名字 | 干什么 | 输入 → 输出 |
| --- | --- | --- |
| **论文格式检查** | 按 GB/T 7714 检查参考文献格式 | 一份 docx → 一份问题清单 + 修改建议 |
| **群消息周报** | 把一周的群聊记录整理成周报 | 聊天记录 → 500 字周报 + 数据表 |
| **课件转复习卡** | 把课件 PDF 变成复习卡片 | PDF → 知识点 + 例子 + 自测题 |
| **简历岗位匹配** | 按 JD 定制简历措辞 | JD + 简历 → 改写版 + 差距清单 |

**✅ 检查点 1**：你能用一句话说清「我要做的 Skill 是 ____，它把 ____ 变成 ____」。

## 第 2 步：把过程口述给 WorkBuddy

这一步很反直觉——**你不用学怎么写 Skill，你只要会"说"**。

### 做法：像带新人一样，把你的做法讲出来

复制这个模板，填空发过去：

```
我想做一个 Skill，名字叫「______」。
不要问我技术细节，我直接用大白话把流程讲一遍，你帮我整理成 Skill。

【我要它解决什么问题】


【我每次是怎么做的】（按步骤写，越具体越好）
1.
2.
3.

【输出要长什么样】
（格式、长度、存成什么文件）

【我最在意的三条规矩】
比如：不许编造数据 / 必须标出处 / 不许直接改我原文
1.
2.
3.

【我踩过的坑】（有过就写，没有就删掉这栏）


听明白了吗？先复述一遍你的理解，我确认后你再生成 Skill。
```

### 关键：`【我最在意的三条规矩】`这一栏千万别空

这是 Skill 和普通 Prompt 最大的差别。**规矩 = 防止它偷懒或编造的护栏。**

真实例子（来自我们社群的早报 Agent 案例）：

| 规矩 | 防的是什么 |
| --- | --- |
| 每条必须带真实链接，不许自己编 | 防大模型"幻觉"编造来源 |
| 福利信息发布前必须核实兑换码已到位 | 防"空头支票"，发出去收不回来 |
| 不许直接改我的原文件，只能另存新文件 | 防误操作把原始资料毁了 |
| 不确定的地方必须标出来，不许猜 | 防它以确定的语气说错话 |

### 如果你的流程讲不清怎么办

跟它说：

```
我自己也说不清步骤。我给你 3 份我以前做出来的成果（等下上传），
你从这些成果里反推出我的标准流程，然后整理成 Skill。
推完之后把流程讲给我听，我来补充漏掉的。
```

**✅ 检查点 2**：WorkBuddy 复述了一遍它对流程的理解，你确认了。

---

## 第 3 步：让它生成 Skill

确认理解无误之后，发这一句：

```
理解没问题。现在帮我生成这个 Skill：
1. 生成完整的 Skill 文件，包含名称、用途说明、分步骤的执行流程
2. 把我给的"三条规矩"写进去，并且写成它必须遵守的硬性规则
3. 告诉我这个 Skill 被安装到了哪里（给出完整路径）
4. 给我 3 个调用它的示例指令，我照着就能用
```

它会自动完成文件的创建和安装。

> 💡 **你不需要看懂生成的文件。** 扫一眼就行，重点确认三件事：
> - 流程跟你的说法对得上吗？
> - 那三条规矩写进去了吗？
> - 有没有多出什么你没说过、但你其实不想要的要求？（有就让它删掉）

**✅ 检查点 3**：它给了你 Skill 的安装路径和调用示例。

---

## 第 4 步：试跑第一次（一定会不满意，这很正常）

**别等以后用，现在就跑。**

```
用刚做好的「______」Skill 处理一下这个：
______（传一个真实文件 / 贴一段真实内容）

跑完告诉我：
1. 你是按哪几步做的
2. 哪一步你不确定，是猜的
3. 输出里你自己觉得最没把握的是哪一部分
```

> 💡 第 2、3 问是关键。**让 AI 自己交代"哪里是猜的"，比你自己检查快 10 倍。**

### 检查三件事

| 检查项 | 怎么看 |
| --- | --- |
| **内容对不对** | 打开生成的文件扫一遍，信息准确吗？ |
| **格式对不对** | 长度、结构、文件名，跟你要求的一致吗？ |
| **规矩守没守** | 那三条硬性规则，它真的执行了吗？ |

---

## 第 5 步：迭代——改三次就稳了

**第一次跑不完美是正常的。** 你不用改任何代码，**只改说法**。

### 高频微调场景

| 你觉得…… | 就这样说 |
| --- | --- |
| 内容跟我想的不一样 | 「你第 3 步理解错了，我要的是××，重写这一步」 |
| 输出太长/太短 | 「结果控制在 500 字以内，超了要精简」 |
| 规矩没守住 | 「我说过不许编造来源，你第 4 条编了一个，重做，找不到就写"未找到"」 |
| 格式不对 | 「输出改成表格，列名用：名称 / 时间 / 负责人 / 状态」 |
| 想加一步 | 「加一步：最后用一句话总结最重要的发现」 |
| 想删一步 | 「第 2 步没用，删掉，直接从第 1 步跳到第 3 步」 |

**每次改完，让它用同一个输入重跑一次，对比前后差别。**

**经验值**：**改 2–3 次**基本就稳定了。如果改了 5 次还不行，说明你的流程本身还没想清楚——回去重做第 2 步。

**✅ 检查点 5**：你至少改过 1 轮，并且对比过前后结果。

## 5. 卡住了怎么办

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 想不出做什么 Skill | 目标太大 | 从小事开始：改一段话、检查一个格式、整理一次笔记。**越小越容易成功** |
| 流程自己都说不清 | 这件事你还没形成套路 | 换一件事；或者上传 3 份历史成果让它反推 |
| 生成完不知道怎么用 | 没拿到调用示例 | 直接问：「给我 3 个调用它的例子，我照着说」 |
| 装了但好像没生效 | 调用时没带上 Skill 名字 | 明确说「用 ___ Skill 处理这个」 |
| 每次都跑得不一样 | 流程里有模糊表述 | 回第 5 步，把模糊的地方改成明确的数字和格式要求 |
| 它还是编造内容 | 规矩没写成硬性约束 | 说「把'不许编造'写成必须执行的硬规则，违反了要明确告诉我」 |
| 想改别人分享的 Skill | 需要先拿到文件 | 请对方导出文件夹给你，或者在群里问我要 |
| 改了很多次还是不理想 | 可能这件事不适合做成 Skill | 用第 1 步的三个标准重新筛一遍 |

## 6. 举一反三：Skill 还能怎么玩

| 玩法 | 怎么做 |
| --- | --- |
| **组合成工作流** | 做 3 个 Skill 串起来：`资料整理` → `初稿撰写` → `质量审核`，一句指令跑完 |
| **给社团用** | 把往届活动 SOP 做成 Skill，换届时新一届直接继承，不用重新摸索 |
| **给全班用** | 做「选修课作业格式检查」Skill，导出发到班群，一次帮 50 个人 |
| **给简历加素材** | "我独立设计并落地了 X 个 AI 自动化技能，服务班级 50+ 人"——这行字可以直接写进简历 |
| **做成比赛作品** | 把 Skill + 使用数据整理成一份案例，可以参加 AI 应用类比赛 |
| **持续升级** | 每次用完发现新问题就改一句，一年后你会有十几个越用越好用的专属技能 |

## 附录：给想深挖的同学

### Skill 的文件长什么样？

它本质上就是一个**文件夹**，里面至少有一个 Markdown 文件（约定叫 `SKILL.md`），内容是：

```
---
name: 技能名称
description: 一句话说明这个技能干什么、什么时候用
---

# 正文：分步骤的作业手册

## 第 1 步：……
## 第 2 步：……
## 必须遵守的规则
- ……
- ……
```

**安装位置分两种：**

| 级别 | 位置 | 适用范围 |
| --- | --- | --- |
| **用户级** | `~/.workbuddy/skills/` | 你所有项目都能用 |
| **项目级** | `{项目文件夹}/.workbuddy/skills/` | 只在那个项目里能用，方便团队共享 |

给同学分享的，一般是**用户级**（装一次到处能用）。

### 为什么 Skill 比 Prompt 更强？

因为它们解决的是不同层次的问题：

| | Prompt | Skill |
| --- | --- | --- |
| 本质 | 一次性的口头指令 | 可复用的书面手册 |
| 生命周期 | 说完就忘 | 长期存在，可持续改进 |
| 能否组合 | 难 | 能，多个 Skill 可以串联 |
| 能否传递 | 靠复制粘贴 | 能，作为一个文件夹传递 |

**Prompt 是"跟它说话"，Skill 是"给它立规矩"。** 规模一大，规矩才靠得住。

### 我们社群的真实标杆案例

参考 `【案例学习1】腾讯云AI校园早报_Agent全流程说.pdf`——那位同学把"每天做一份 AI 早报"这件事，做成了一套完整流程：

- 每天 10:30 自动触发
- 联网搜索过去 24 小时的重要 AI 新闻
- 筛选 6 条最适合大学生看的
- 每条写清「发生了什么 / 跟学生有什么关系 / 来源链接」
- 输出 Markdown 存档 + 推送群消息 + 写入在线表格

他在文档最后总结了一句话，很值得记住：

> **触发层**：什么时候跑？频率？
> **任务层**：要做什么？输出什么？
> **能力层**：需要联网/文件/脚本/外部工具吗？
> **交付层**：产物是什么？给谁看？
>
> 把这 4 个问题答清楚，你的 Prompt 雏形就出来了。

**你本周做的那件事，就是这套方法的最小版本。**
